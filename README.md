## `> whoami`

I like learning through **real projects**.

My GitHub is less about staying inside one stack and more about exploring what can be built with different tools, languages, and approaches. I move between web development, automation, utilities, developer tooling, AI-enabled software, and lower-level experiments depending on the problem I'm trying to solve.

A pattern shows up across the projects:

> **build → experiment → understand → iterate**

That usually means trying something practical first, then improving it as the idea becomes clearer.

| Direction                     | What it looks like                                                                          |
| ----------------------------- | ------------------------------------------------------------------------------------------- |
| 🧩 **Practical software**     | Tools, utilities, applications, and experiments built around an actual use case             |

## My Development Style

### `01` — Learn by building

I tend to understand technologies by putting them into something real.

### `02` — Explore beyond one stack

My projects span multiple languages and ecosystems instead of staying locked into a single toolchain.

### `03` — Turn experiments into usable tools

When an idea works, I like pushing it toward something reusable, configurable, or practical.

### `04` — Modify, rebuild, improve

I don't limit myself to building from zero. Forking, adapting, extending, and reshaping existing software are also part of how I explore ideas.
